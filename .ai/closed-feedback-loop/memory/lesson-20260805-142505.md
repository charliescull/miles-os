# Lesson

## Situation

A large OS initiative was approached as incremental vertical slices with protected existing behavior and explicit verification requirements.

## What went wrong or worked

The architectural decomposition and focused checks worked: TypeScript, focused ESLint, diff checks, and quick-capture tests passed. However, the loop reached its iteration limit while critical evidence remained incomplete. Supabase migration/concurrency/manual replay checks were not run, full lint still had 42 errors, and verification artifacts contradicted the successful build result. The read-only workspace also prevented writing the review artifact.

## Evidence

- Focused ESLint, TypeScript, diff checks, and all three quick-capture tests passed.
- Full lint failed with 42 errors.
- Supabase migration and replay/concurrency checks remained unexecuted.
- Verification artifacts incorrectly reported the current build as blocked.
- Review verdict: `FIX_REQUIRED`.
- `review.md` could not be written because the workspace was read-only.

## Better heuristic for next time

Before expanding implementation scope, require a verification ledger with one explicit status per acceptance check: `passed`, `failed`, or `not run`. Do not allow a release/review summary until critical persistence, migration, and replay checks have evidence, and regenerate summaries from current command output rather than carrying forward stale statuses.

## Applicability

Applies to multi-slice agent runs involving database migrations, offline/retry behavior, or feedback-loop artifacts.
