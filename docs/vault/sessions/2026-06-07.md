## Update — comp parts-filter fix

Two-layer fix for parts/accessories polluting the eBay comp price:
1. **Semantic** — added `Comparable.is_part`; comps.py instruction asks Claude to flag
   rotors/PCBs/lids/motors/"for parts" listings; `_drop_parts` removes them before the
   DB/math.
2. **Statistical backstop** — `calc.price_outlier_filter` drops comps below
   `comp_outlier_floor_ratio` (0.4) × median once there are ≥ 4 comps.

Calc tests: 18 → **22, all green**. Proven live on the Sorvall case that previously
read −57%: the semantic filter caught 5 parts (lid lock, 2 control PCBs, rotor, another
board) and the stat backstop dropped 2 cheap mislabeled "units" → target price corrected
to a clean $3,481.65, **ROI −57% → −11.5%** (still rejected, but now correctly: genuinely
unprofitable + only 1 unit sold in 30 days). New env knobs: `COMP_OUTLIER_FLOOR_RATIO`,
`COMP_MIN_FOR_OUTLIER_FILTER`.

## Update — self-learning layer (unified profit scorer)

Built a feedback loop that learns to predict an opportunity's REALIZED net profit.
Chose a **pure-python ridge regression** (closed-form, standardized) — zero deps, which
sidesteps the sklearn/numpy-on-3.14 risk and means scoring needs nothing extra.

- `src/ml/`: `features.py` (19 deterministic features), `model.py` (`ProfitScorer`),
  `train.py` (`python -m src.ml.train` — pulls outcomes, recomputes true realized profit
  from actual sale price, CV-grid-searches lambda, stores active model), `score.py`
  (cached active-model scoring; cold-start falls back to deterministic net profit).
- Wired into `agent.process_item` (best-effort): snapshots features + writes
  `model_score`/`model_confidence` per opportunity.
- 35 tests (6 new ML): model hits R²>0.99 / CV-R²>0.95 on synthetic linear data.
- Migration `db/0002_ml.sql` (outcome/score columns + `ml_model` table) — **NOT yet
  applied; run it in the Supabase SQL Editor.**
- Dashboard redeployed with Bought / Pass / Mark-sold actions (service-role API route
  `app/api/decision`, `SUPABASE_SERVICE_ROLE_KEY` added to Vercel) + a model-score line.

Loop: scraper scores each alert → you mark bought/passed and log the sale price →
`python -m src.ml.train` → sharper scores next run.
