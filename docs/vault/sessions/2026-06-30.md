# Session Log — 2026-06-30

## Summary

Shipped the entire previously-built-but-never-deployed batch (JARVIS reskin, COMMAND
center, PWA, 15-min Telegram alerts) to production, debugged a multi-layer deploy
failure, and added a new **cancel appointment** command.

The deploy had been silently failing for days. Root causes, fixed in order:
1. New code was never committed — committed & pushed.
2. **Every Vercel deploy was failing validation** because `vercel.json` declared a
   `*/5 * * * *` cron, which the Hobby plan forbids (daily-only). Removed the alert
   cron from `vercel.json`; the 5-min cadence is handled by an external cron-job.org
   job hitting `/api/cron/alerts`.
3. The Edge middleware (`proxy.ts`) didn't reliably resolve `CRON_SECRET`, so the
   alert route 307-redirected to /login. Added `/api/cron` to `PUBLIC_PATHS`; the
   route enforces its own Bearer-token auth in the Node runtime (route.ts:103).
4. A leftover **project-level `CRON_SECRET` from May 27** was overriding the shared
   env var, so runtime saw the wrong value → 401. Corrected/removed the duplicate.

Final state: `/api/cron/alerts` returns 200 with auth, 401 without. cron-job.org job
fires every 5 min. PWA assets, COMMAND center, new look all live.
