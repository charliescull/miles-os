### Gotcha learned (Windows dev)
- `next dev` node processes DON'T have the project in their `.exe` Path (Path = Node install dir). Killing by `$_.Path -like "*OS System*"` never matches → orphaned dev servers pile up → many node procs exhaust the Windows session → Turbopack child-process panic `0xc0000142` (STATUS_DLL_INIT_FAILED) → every page 500s. Fix: kill the dev node procs by PID (or via port-3000 owning process), and DON'T run `npm run build` while `next dev` holds `.next`. Clear `.next` if state is corrupted.
